# 界面设计

> 本文描述**当前实际实现**，以 `src/frontend/index.html`、`css/style.css`、`js/ui.js` 与
> `src-tauri/tauri.conf.json` 为准。
>
> 初版本文档描述的界面**没有实现**，其中「热门干员快捷栏」与「点击计算按钮」两处差异最大，
> 见文末「与初版设计的差异」。

## 一、页面结构

单页，纵向五块（`index.html`，最大宽度由 CSS 控制）：

```
┌──────────────────────────────────────────────────────────────┐
│  ⚔️ ArkDMGCalc                                                │
│  明日方舟干员输出计算器                                        │
│  🎯 敌人数据                                                  │
│    生命值 [50000]  攻击力 [800]  防御力 [600]  法术抗性 [50]  │
│    敌人类型 [普通 ▼]   ← 普通 / 精英 / 领袖                    │
│  👤 干员配置                                                  │
│    [+ 添加干员] [+ 添加干员] [+ 添加干员] [+ 添加干员]         │  ← 固定 4 个槽
│  📋 基础属性                                                  │
│    每个已填槽一张卡：生命值 / 攻击力 / 防御力 / 法术抗性 / 攻击间隔 │
│  📊 计算结果                                                  │
│    每个已填槽一张卡，按结果类型分流（见第四节）                 │
│  📝 说明                                                      │
│    子职业通用说明在前，干员个人说明在后（按选择顺序）           │
└──────────────────────────────────────────────────────────────┘
```

**没有「计算」按钮**：所有输入（敌人四项、敌人类型、槽内每一项）都绑定 `input` / `change`
事件，改动即调用 `updateResults()` 重算。敌人类型 `grade` 决定元素损伤的 EP 容量
（普通/精英 1000、领袖 2000）。

## 二、干员选择器

点击空槽 → 弹出覆盖整个视口的抽屉（顶部对齐，不垂直居中，避免列表变长时跳动）：

```
┌──────────────────────────────────────┐
│ 选择干员                              │
│ [搜索干员（中文名，支持部分字符，如 推进）] │
│ [主职业 ▼]  [子职业 ▼]                │
│ ┌──────────────────────────────────┐ │
│ │ 六星  推进之王                    │ │  ← 三级选择结果列表
│ │ 五星  德克萨斯                    │ │
│ └──────────────────────────────────┘ │
└──────────────────────────────────────┘
```

两条并行的选择路径：

1. **三级下拉**：主职业 → 子职业 → 干员列表。下拉里**只出现有数据的子职业**；
   干员按**星级降序**排列（同星级保持数据顺序）。
2. **搜索框**：输入即过滤**全库**，按显示名的**子串**匹配（大小写不敏感），命中段用 `<mark>` 高亮，
   结果同样按星级降序。搜索结果项显示头像、星级、名称、`主职业 · 子职业`。

搜索的匹配范围有明确限制（注释里写死了）：

- **只匹配显示名 `op.name`**。不匹配内部 id / 代号（`char_*`、`token_*`）、
  子职业 id、职业英文等任何其它字段。初版文档写的「支持中文名/英文名模糊搜索」**不成立**。
- 召唤物等有持有者的单位，显示名是 `持有者名·单位名`，其中**只有 `name` 部分参与高亮**。
- 清空搜索框即恢复三级下拉视图。

**点击某条才入槽**（不是悬停或回车），随后关闭抽屉。抽屉可通过点击遮罩关闭。

## 三、槽位配置项

每个槽（最多 4 个）的配置项，实测取值：

| 控件 | 取值 | 联动约束 |
|---|---|---|
| 精英化 | `E0` / `E1` / `E2`（按该干员实际阶段数） | 降精英化会**夹紧并回收**越界项 |
| 等级 | 数字输入，`min=1`，`max=该阶段 maxLevel` | 切换精英化后等级上限随之变化 |
| 信赖% | 数字输入，`0–100` | — |
| 技能 | 该干员技能名下拉 | 可选技能数受精英化限制：E0 只有 1 技能、E1 到 2 技能、E2 全开 |
| 技能等级 | `Lv1`–`Lv7`、`专一`/`专二`/`专三` | 按精英化限制档位：**E0 最高 Lv4、E1 最高 Lv7、E2 才可专精** |
| 潜能 | `1阶 - <描述>` … `N阶`，外加「无潜能」 | 潜能对 ATK/DEF/MAX_HP 的加算计入面板 |
| 模组 | 证章 / X 模组 / Y 模组 各 1~3 级 + 「无」 | 效果模组需 **E2 且等级 ≥ 解锁等级**（四星 40 / 五星 50 / 六星 60）；未达显示禁用，降精英化或降等级自动回收为「无」 |

槽内改动后：先做越界修正（夹紧技能等级与技能序号、回收未解锁模组），再 `renderSlot()` 重绘该槽，
最后 `updateResults()` 重算全部。

**没有技能选择器的情形**：干员本身无技能；召唤物只有 `skcom_` / `sktok_` 占位技能
（如医疗探机）——带注入技能的攻击型召唤物（如 Mon3tr）正常显示技能。此时仍可计算常态。

## 四、结果渲染：按类型分流

结果卡分四种渲染形态（`ui.js`）：

| 形态 | 判定 | 显示 |
|---|---|---|
| 治疗型 | `result.type === 'heal'` | 常态 HPS / 技能期 HPS / 总治疗量 / 周期 HPS；若同时有输出，追加技能期 DPS 与总伤。吟游者的「技能期攻击间隔」标签改为**治疗间隔**（它是每秒一跳，不是攻击） |
| 永续/切换 | `isToggle` 或 `isPermanent` | 只显示 **DPS**（永续没有「总伤」概念）+ 技能期间隔 + 技能期 ATK |
| 触发型 | `cycleDps !== null` | **总伤** + **循环 DPS** + 技能期间隔 + 技能期 ATK |
| 瞬发型 | 其余 | 技能期总伤（`skillDps` 为 0 时不显示 DPS 行）+ 常态 DPS + 技能期间隔 + 技能期 ATK |

**多类型混合伤害**逐类型渲染色值，只显示 > 0 的档位，多档用 `+` 连接：

- 技能期读 `dmgTypes`（`{类型: {skillDps, skillTotalDamage, cycleDps}}`）
- 常态化读 `normalTypes`（`{类型: {dps}}`）
- 两者都不存在时回退单类型整数值

伤害类型配色（CSS 变量）：物理 `#ff6b6b`、法术 `#b388ff`、真实 `#f5f5f5`、元素 `#9e9e9e`。
元素数值与普通伤害用 `dmg-group` 紧凑排列。

## 五、说明区

按选择顺序渲染：**子职业级说明（`notes.json` 的 `__subprof_<子职业id>`）在前，
每个子职业只出现一次**；随后是干员个人说明（`notes.json` 的 `<干员id>`）。
没有说明的干员跳过。说明文本是纯手工维护的，重抓干员数据不会覆盖它。

Tauri 窗口（`src-tauri/tauri.conf.json`）：

```
标题   ArkDMGCalc - 明日方舟干员输出计算器
尺寸   1400 × 950，最小 1000 × 700，可缩放，启动居中
```

**不考虑移动端**（Tauri 桌面窗口固定比例即可）。

## 七、与初版设计的差异

| 初版文档 | 实际实现 |
|---|---|
| 「热门干员快捷栏」：搜索框下按使用率硬编码 8 职业热门干员卡片 | **没有此功能**。`getPopularOperators()` 虽然仍叫这个名字，但它返回的是**索引里的全部 502 条**，供三级下拉分组用；界面上没有热门推荐区 |
| 「点击计算按钮，下方展示结果」 | **没有计算按钮**，改输入即时重算 |
| 搜索支持「中文名/英文名模糊搜索」 | 只按**中文显示名子串**匹配，不匹配英文名、内部 id、子职业 |
| 干员配置在结果区上方「选中已添加的干员，下方展开配置」 | 配置**直接内嵌在每个槽位里**，无需先选中 |
| 窗口最小 1200×800 | 1000×700 |
| 最多 5 个干员槽 | **4 个**（`state.js` 的 `slots` 四项、`ui.js` 的 `i < 4`） |
