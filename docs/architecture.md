# 架构设计

## 整体架构

```
┌─────────────────────────────────────────────────┐
│                  Tauri 窗口                      │
│  ┌───────────────────────────────────────────┐  │
│  │            Web 前端 (WebView)              │  │
│  │                                           │  │
│  │  ┌─────────┐ ┌─────────┐ ┌────────────┐  │  │
│  │  │ UI 交互  │ │ 计算引擎 │ │ 数据管理层  │  │  │
│  │  └─────────┘ └─────────┘ └────────────┘  │  │
│  │        ↕ Tauri IPC (invoke)  ↕            │  │
│  └───────────────────────────────────────────┘  │
│                                                 │
│  ┌───────────────────────────────────────────┐  │
│  │            Rust 后端                       │  │
│  │                                           │  │
│  │  ┌──────────┐ ┌──────────┐ ┌──────────┐  │  │
│  │  │ Wiki抓取  │ │ 页面解析  │ │ 定时调度  │  │  │
│  │  └──────────┘ └──────────┘ └──────────┘  │  │
│  └───────────────────────────────────────────┘  │
└─────────────────────────────────────────────────┘
         ↕ HTTP                    ↕ 文件系统
    PRTS Wiki                  data/ 目录
```

## 职责划分

### Rust 后端

后端只做两件事：**抓数据**和**存数据**。计算逻辑全部放在前端。

- **fetcher**: 从 PRTS Wiki 抓取干员页面内容
- **parser**: 解析页面 markdown，提取结构化数据（属性、技能、天赋）
- **scheduler**: 管理更新时机，启动时检查是否需要更新

后端暴露的 Tauri IPC 命令：
- `check_update()` → 检查是否需要更新数据
- `fetch_operator(name)` → 抓取单个干员数据
- `fetch_operator_list()` → 抓取干员列表
- `get_local_operators()` → 获取本地已缓存的干员列表
- `get_operator_data(name)` → 读取本地干员 JSON

### Wiki 解析要点

技能数值的运算方式（直接加算/直接乘算/最终加算/最终乘算）通过 HTML 颜色编码存储：

```html
<!-- 普通描述模式（算法_1） -->
<span class="xxx算法_1"><span style="color:#0098DC;">+35%</span></span>

<!-- 算法模式（算法_2） -->
<span class="xxx算法_2" style="display:none;">
  <i class="mdi mdi-plus" style="color:#007DFA;"></i>
  <b><span style="color:#007DFA;">35%</span></b>
</span>
```

颜色与运算方式映射：
- `color:green` → 直接加算 (direct_add)
- `color:#007DFA` → 直接乘算 (direct_mul)
- `color:orange` + `mdi-plus` → 最终加算 (final_add)
- `color:orange` + `mdi-close` → 最终乘算 (final_mul)

解析时提取 `算法_2` 的 HTML，匹配 `<i>` 标签的颜色和图标类名，即可确定每个数值的运算方式。

### Web 前端

前端负责所有计算和界面展示。

- **data/**: 从后端获取数据，管理本地状态
- **calculator/**: 各技能类型的计算模块（见 skill-types.md）
- **ui/**: 界面交互逻辑

### 为什么计算放前端

1. 计算逻辑需要频繁迭代和调试，JS 改完刷新即生效，不需要重新编译 Rust
2. 计算本身不涉及敏感操作或系统权限，不需要后端执行
3. 前端可以直接操作 DOM 展示结果，不需要跨层传递
4. 降低 Rust 侧的复杂度，后端只做它擅长的 I/O 操作

## 数据流

```
启动
  │
  ├─ 读取 data/meta.json（上次更新时间）
  │   ├─ 超过 24h → 后台静默抓取更新 → 写入 data/
  │   └─ 未超时 → 跳过
  │
  ├─ 前端加载 → 调用 get_local_operators() 获取干员列表
  │
  ├─ 用户选择干员 → 调用 get_operator_data(name) 获取详情
  │
  ├─ 用户选择技能/等级 + 填入敌人数据
  │
  └─ 前端 calculator 模块执行计算 → 展示结果
```

## 错误处理

- 网络不可用：使用本地缓存数据，界面提示"数据可能不是最新"
- 抓取失败：记录日志，下次启动时重试，不阻塞用户使用
- 解析失败：该干员标记为"数据不完整"，跳过但不影响其他干员

## 依赖

### Rust 端
- `tauri` - 框架核心
- `reqwest` - HTTP 请求
- `serde` / `serde_json` - JSON 序列化
- `tokio` - 异步运行时
- `chrono` - 时间处理

### 前端
- 纯 Vanilla JS，暂不引入框架（保持轻量，后续需要时可加 Vue/React）
